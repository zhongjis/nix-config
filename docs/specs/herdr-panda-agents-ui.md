# Spec: herdr-panda agents UI (Agents panel, rail, beads view)

Status: implemented and deployed (the skill side waits for agent-skills to land); in-app rendering checked, interactions pending. The 2026-11-26 review fixes (two whole-change reviews) and the removal of the screen preview are in the working tree, not yet deployed.

Source: the 2026-11-26 critique and audit of the herdr-panda mods (`fleet`, `panda-focus`, `panda-subagents`, `panda-tabs`), their session hooks, and the `orchestrate-using-herdr-app` skill. Score 20/40. The skill side of the shared contracts is specified in agent-skills `docs/specs/orchestrate-using-herdr-app-ui-contract.md`.

## Problem Statement

The Agents panel (`mods/fleet`), the agent rail (`mods/panda-focus`) and the tab bar disagree about the same agent: the panel builds its own name instead of the shared name rule, and reads `terminals().status_ms`, which the app freezes at start, so an agent that changed an hour ago reads "idle 4d".

For an orchestrator, the panel lists terminals, not tasks. A reviewer shows as a loose card and triggers "1 worker has no bead", because review beads are children of the task and are never loaded. A task waiting on another task reads "Queued", like a task waiting for a slot, and carries its raw bead id. A failed or abandoned settle reads green "Done". A worker's own prompt shows "Needs you" with an Answer button that types into the worker, although the skill makes the orchestrator answer worker prompts, and nothing is recorded on the bead. A bead hold on a live worker shows only as a strip caption.

Bead events are five newest-first rows. The parser cuts every value at the first space, so a decision reads "no" or "Close". Nothing shows the orchestrator and its workers talking, whose turn a task is on, the session's mode or slots, or the dependency order. Five of seven open session epics belong to orchestrators that ended without `--off`, and no view shows them.

Smaller defects: Ctrl+Shift+A is dead while the panel has the keyboard (a stale `mod:fleet` binding the Nix merge never prunes); the snooze menu calls `closeOverlay` without importing it; Snooze, Wake and Forget have no key; dim text is 3.57:1 on the sidebar; metadata is 11 px; seven targets are under 24 px; hibernating a worker drops its `BEADS_ACTOR`, `ORCH_BEAD` and `BEADS_DIR`, so a worker revived from the window reports under the wrong identity.

## Solution

One set of shared modules in `mods/shared/` owns names, status words, times, the change clock, bead-event parsing, task assembly and `bd` access. Every agent surface imports them, so the rail, the tabs, the panel and a new beads view say the same thing.

The Agents panel makes tasks the rows of an orchestrator's tree. Each task card holds its worker, its review rounds, its PR and its dependencies, a labeled lifecycle strip, and a turn chip: Worker's turn, Orchestrator's turn, Your turn, Waits on a task, Waiting for a slot, Queued, or the settle result. The header shows the session's mode, slots, source ticket and task progress. A task's detail opens beside the tree from 640 px wide, and its bead events become a timeline grouped into rounds, with an actor on every event, the line colored by who held the task, and a time-held summary. A question that waits on you sits above its answer field, and the answer goes to the orchestrator, which records the decision.

Live signals: a worker's status flip (idle to working, working to idle) and the skill's `orch.in` label animate a pulse along the spine natively. The rail card of an orchestrator shows task progress and whose turn, and flashes each send or report for 3 s.

A new `beads` mod, opened as a tab, shows every open session epic, the selected epic's `blocks` graph, and an inspector with remote ticket state, local facts and every session that touched the bead.

## User Stories

1. As the user, I want the panel, the rail and the tabs to name an agent the same way, so that I trust the panel shows the agent I picked.
2. As the user, I want every age to match the core's live status time, so that "idle 4d" never appears for an agent I used an hour ago.
3. As the user, I want an orchestrator's tree to list tasks, each with its worker, reviewers and PR, so that I read the work, not the terminals.
4. As the user, I want each task to say whose turn it is, so that I see at a glance whether the worker, the orchestrator or I hold it.
5. As the user, I want a task waiting on another task to name that task, so that I know what unblocks it.
6. As the user, I want a task waiting for a `--max` slot to say so, so that I don't confuse it with a dependency.
7. As the user, I want a failed, abandoned, blocked or uncertain settle shown as such, so that only success reads green.
8. As the user, I want review rounds inside their task, with their status, so that a reviewer never reads as a worker with no bead.
9. As the user, I want a hibernated worker shown with a moon and a Revive action, so that part of the tree never vanishes.
10. As the user, I want the header to show the mode, slots, source ticket and progress, so that I know how the session runs.
11. As the user, I want a task's history as a timeline of rounds with actors and durations, so that I can read what happened and where the time went.
12. As the user, I want decisions shown with their whole question and answer, so that a decision never reads as one word.
13. As the user, I want "Your turn" only for questions escalated to me, so that worker prompts the orchestrator answers don't pull me in.
14. As the user, I want the question above the answer field, so that I answer what I can read.
15. As the user, I want my answer sent to the orchestrator with its bead, so that the decision is recorded and the hold clears.
16. As the user, I want a pulse along the tree when the orchestrator sends to a worker or a worker reports, so that I see the fleet talking without reading logs.
17. As the user, I want an orchestrator's rail card to show task progress and whose turn, so that I can scan the rail without opening the panel.
18. As the user, I want one key that jumps to the next agent or task needing me, so that I never hunt through folded shelves.
19. As the user, I want the detail beside the tree when the panel is wide, so that I keep my place.
20. As the user, I want an agent without workers to show its own last report and answer field, so that the panel is useful for every agent.
21. As the user, I want a beads view of every open session, its dependency graph and each bead's remote state and sessions, so that I can manage orchestration beyond one panel.
22. As the user, I want sessions whose orchestrator ended without `--off` flagged with a way to close their epic, so that stale sessions don't linger.
23. As a keyboard user, I want keys for snooze and wake, a visible focus in the panel, and Ctrl+Shift+A to close the panel from inside it, so that I never need the mouse.
24. As a low-vision user, I want readable text at 4.5:1 and at least 12 px, and targets of at least 24 px, so that I can read and hit everything.
25. As the user, I want a worker revived from the window to keep its bead identity, so that its reports land on its bead.

## Implementation Decisions

### Shared modules (`mods/shared/`)

Each consumer links the files it needs from its own folder (`<mod>/name.js -> ../shared/name.js`); the Home Manager module copies `"${./mods}/<mod>"` with `cp -rTL`, so links resolve. Consumers: `fleet`, `panda-focus`, `panda-subagents`, `panda-tabs` (names and words), `beads`. `panda-focus/name.js` and `panda-focus/tree.js` move to `shared/` unchanged in behavior. All modules except `bd.js` and `clock.js` import nothing from `"herdr"` so node tests load them.

- `name.js` (moved): `namer()` as today, plus `termName(k, namerFn)`: a listed agent goes through `namerFn`; an unlisted sub-agent uses its hc name (`k.name`, e.g. `w-abc-12-keys`), else `namerFn(k)`.
- `tree.js` (moved): `kidStatus`, `descendants`, `treeStatus`, `subAgents` unchanged, plus `isOrchName(s)`: a pane, tab or title starting `[o]` (any case). The panel and the rail both detect orchestrators with it.
- `revive.js` (new, pure: `hc` is passed in): the one revive path of the Agents panel and the sub-agents popup. It reads the finished terminal with `hc get <address> --json` and starts a new one with its launch contract: the argv's whole `env K=V…` prefix (PATH with the agent shims, the bead identity, values with spaces too; the resume label's own prefix when the argv has none), the agent line of the `resume` label, the name, cwd, parent (while it is live), `--no-notify` when it had notify off, `--outlive-parent` unless it died with its parent, and every label except the runtime ones (`resume`, `resume.pid`, `hibernated`, `hibernate`, `settled`, `snoozed`, `orch.in`, `where`, `herdr.*`). `hibernate=ok` comes back only when the old terminal had it, never on Codex. The argv goes after `--`. The finished terminal is removed only after the new one started and gave its address; a failed start keeps it and its resume label. An orchestrated terminal (an `orch` label, or `orch-context` naming the skill's `worker-context.sh`) first passes the skill's own launch checks: `start-worker.sh <name> <cwd> <ORCH_BEAD> --kind <kind> --resume <session> --check`, run beside that script with the terminal's env. So a reviewer whose review bead closed, a worker no longer assigned, or a reviewer whose checkout a worker is editing is refused and nothing starts; one whose bead, kind, session or skill script cannot be read is refused too. The slot check needs the orchestrator's `--max`, which the panel does not have; a revived agent resumes idle and takes a slot only when the orchestrator sends it work.
- `words.js`: one vocabulary. Agent words: `working` "Working", `blocked` "Needs you", `done` "Done", `idle` "Idle", `hibernated` "Hibernated", `ended` "Ended", `failed` "Failed"; "Supervising" is retired (a parent waiting on sub-agents reads "Working"). Task turn words: `worker` "Worker's turn", `orch` "Orchestrator's turn", `you` "Your turn", `waiting` "Waits on <key>", `slot` "Waiting for a slot", `queued` "Queued", `done` the settle result: "Succeeded", "Failed", "Abandoned", "Blocked", "Uncertain", or "Merged, releasing" before `settled`. Report kinds: `ready-local` "Ready for local review", `pushed` "Pushed", `pr-opened` "PR opened", `blocked` "Blocked", `done` "Done". Event words for every name in the skill's `event.sh` allowlist. Reason codes as sentences (`needs-user` "Waiting on your answer", `remote-closed` "Ticket closed remotely", `pull-skipped` "Ticket pull skipped"). Times: `ago(ms, now)` → "just now", "5m", "2h", "3d"; `took(ms, now)` → "9s", "4m", "1h 5m", "2d 3h"; never "now ago".
- `events.js`: `KNOWN_KEYS` (every key the skill and the worker skill write: `agent terminal worktree kind result head pr reason by q a detail merged_sha flags max needs round bead last-reviewed stopped run bot_rounds after handoff tab session question reviewer model`). `parseEvent(comment)` reads the first line `event=<name> …`: a field starts at `<key>=` where `key` is the first token or any `KNOWN_KEYS` member preceded by a space, and runs to the next such start, so values keep their spaces. A quoted value (`key="…"`, which the skill's `event.sh` writes for a value with a line break, CR or tab, a leading `"`, or a space followed by `key=`) runs to its closing unescaped `"` before a space or the end of the line, with `\\ \" \n \r \t` decoded; the next field then starts at the next `key=`. A `"` without such a close is plain text, so existing comments parse as before. Both specs state this one rule. Returns `{ id, name, fields, at, line, body, actor }` (`id` the comment's; `actor` from the comment author: `o-…` orchestrator, `w-…` worker, `r-…` reviewer, else `user`). `eventsOf(comments)` oldest first. `questionOf(event)`: a `blocked` event's `q=`, else its whole body. `holderAfter(event, prev)` (dispatched, re-instructed → worker; report → orch; blocked with `reason=needs-user` → you, other blocked → orch; decided, ready, merged → orch; settled → done; reaped keeps done and a question waiting on you, else orch; others keep `prev`). `rounds(events)`: a round starts at each `dispatched` or `re-instructed`; events before the first form round 0. `held(events, now)`: per event the span until the next (the last until `now`) and its holder, plus totals per holder; a span held as done ends where it starts, so a settled task's time stops growing.
- `tasks.js`: `sourceLabel(source)` for a session's source in a header (an issue URL's key, "Linear project", a URL's host, else the text). `taskKey(bead)` from `external_ref`'s ticket key (`/ABC-12` path segment or `browse/ABC-12`), else `metadata.key` upper-cased, else the bead id. `lifecycle(bead, events, reviews)` → `{ stop, round, pr, head, ready, merged, settled, result, hold, holdQuestion, holdQuestionId }`: `stop` 0 queued, 1 dispatched (`dispatched`, `handed-off` or `adopted`), 2 review (`review_round` > 0 or a review bead), 3 PR (the newest `pr=` in a report or `ready` event, else `pr_url` metadata, so a replacement PR wins over the old mirror), 4 ready (a `ready` event newer than the newest `pushed` or `pr-opened` report), 5 merged (`merged_sha` or `merged`), 6 settled (`settled`, with `result`, unless a later dispatch or re-instruction superseded it: the task was reopened; a closed bead without one is settled with result `closed`, "Closed", not green). `hold` is `blocked_reason` metadata (or `blocked` status); `holdQuestion` what the newest `blocked reason=needs-user` event written by the orchestrator (an `o-` author) asks (`questionOf`, whole) and `holdQuestionId` that comment's id. `buildTasks({ epic, beads, deps, reviews, comments, terms, listed, hibernated, now })` → task rows `{ id, key, title, url, status, life, worker, reviewers, waitsOn, blocks, slotWait, turn, events, since }`: `worker` is the live terminal named by the newest `w-` dispatch (`terminal=` or `agent=`), else the terminal named like the assignee, else a hibernated row of that name; `reviewers` are review beads (children titled "Review …", assignee `r-…`) as `{ bead, round, open, worker, events }`, by round (the title's `round N`, else the bead's `review_round`, else its place): an open round's terminal may be found by name, a closed round's only by the terminal its own events name, because the skill reuses `r-<stem>` across rounds; `waitsOn` are `blocks` prerequisites not closed; `slotWait` is a `queued needs=slot` newer than the last dispatch. Parsed events are kept per comments list, so a render does not parse them again. `turnOf(task)`: settled → done; `hold` needs-user → you; any other hold → orch; worker working → worker; worker blocked at a prompt → orch; merged → orch; `waitsOn` → waiting; `slotWait` → slot; not dispatched → queued; newest report newer than newest instruction → orch; else worker. `summary(tasks)` → `{ total, counted, done, failed, ready, merged, inPr, you, waiting, working, text }`. Progress counts done tasks, not merges (user decision, 2026-11-26: "merged" read as no progress for sessions without PRs): a task is done once it settles with result `succeeded` (a merged PR counts once it settles; a bead closed without a settle event counts as done); a settled `failed`, `blocked` or `uncertain` task is "failed" and not done; abandoned tasks drop out of the total (`counted`). `text` names what needs the person first ("your turn on ABC-12", or "your turn on N tasks", then "N failed"), then what moves ("N working", then "N PR ready" for a PR whose `ready` event is newer than its pushes and that is not merged), then progress "D/T done"; when every counted task is done it is "all done", and "" when nothing is counted. Examples: "1 working · 1/2 done", "your turn on ABC-12 · 1/4 done", "1 PR ready · 1/4 done", "all done".
- `clock.js`: `Clock` tracks each address's status and the time it last changed. First sight starts the injected fetch at once (`hc get <t> --json`, its `status_ms`) and uses the stale `terminals()` value until it answers; a status change seen later sets now. `takePending()` hands over the fetches started since the last call, so a render can redraw once they land (await them in a task, then notify). `since(address)`, `flip(address)` (the last change: `{ from, to, at }`, for pulses) and `prune(addresses)`.
- `bd.js` (imports `exec`): an orchestrator's session is its newest open epic (by `created_at`, then id) in the rail, the panel, Ctrl/Cmd+Shift+J and `fleet.open` alike; older open epics show only on the beads view. `beadsDir()` (login shell's `BEADS_DIR`, asked once), `bdJson(dir, args)`, `bdConfig(dir, key)`, `newestEpic(epics)`, `loadEpic(epic, dir)` → one Session: the epic's tasks, a `bd list` of each task with `review_round` > 0 (its review beads), then one batched `bd show <epic> <tasks> <review beads> --include-comments --brief-deps` for dependencies and comments (with their ids) together, and the epic's newest `event=mode` (`flags`, `max`). `loadSession(orch, dir)` → `{ session, extra }`: the newest open epic in full, and how many older ones there are. `loadSummaries(orchs, dir)` → the same read per orchestrator from one shared epic list, so the rail and the panel build the same rows; an orchestrator whose read failed is left out. `loadAllSessions(dir)` (every open epic with child status counts). `epicState(dir, id)` and `liveHold(dir, id)` read a bead now (Close epic's recheck; the panel's answer check). Read-only, except `closeEpic(dir, id)`, used only by the beads view on a confirmed click.

### Agents panel (`mods/fleet`)

- Data: `loadSession` for the drawn orchestrator only (its newest open epic), on show and every 10 s while shown and the window is visible; nothing for other orchestrators (the rail's summaries come from `panda-focus`). The first read waits for the window to be visible too.
- Names through `termName`; ages through `Clock`, except the header's time for an agent the rail shows, which is the rail card's own (shared `"panda-focus.since"`, itself from the rail's clock), so both count from the same moment; words through `words.js`. A root's own status keeps `done` (as the rail reads it); only a sub-agent's done reads idle.
- Non-orchestrator roots keep the terminal tree (sub-agents and tools). An agent with no children and no epic shows the solo view: its last report line, Focus or Peek as its place allows, and, when it is blocked, an answer field that types into the agent itself (`hc send --force -- <t> <text>`). An orchestrator's workers get no answer field, also in the terminal tree drawn before its beads load: the orchestrator answers its workers' prompts. There is no screen preview anywhere in the panel, and no `hc read`.
- Session rows (worker, reviewers, a worker at a prompt, a tree node) reach a live agent one way (`model.js reachOf`): Peek when it has no pane (a hidden worker or reviewer), Focus when its pane is on another tab or space, neither when its pane is on the current tab. A reviewer reused across rounds is one row naming every round it held.
- Orchestrator roots: header with name, state and time ("Working 11h 43m"), meta line (program, space, mode chip from the epic's newest `event=mode`, `Slots n/max` under `--max`, source ticket), a progress bar with one segment per task colored by turn, and a summary line. Task cards in dependency order (settled last): key chip, PR chip (with CI mark from shared `panda-spaces.prs` when present), title, labeled strip (Dispatched, Review, PR, Ready, Merged, Settled; the current stop in its turn color), worker line (program icon, name, state, Hibernated with Revive), review rounds ("Review r1 · closed"), turn chip, and a dim line with the newest event and what it unblocks. Waiting tasks: "Waits on ABC-12" with a lock glyph, dashed. Settled tasks fold to one line.
- Detail: from 640 px panel width, beside the tree (tree 340 px); narrower, in place of the tree with a breadcrumb ("← [o] name"). The first frame assumes the 368 px default width. Order: Your-turn block (question wrapped, then the answer field), strip, links (ticket opens with `cx.open_url`, PR opens in the PR panel when the feed has it: a full URL matches only the same host, owner, repo and number; a bare number only when one repo has it), sessions (worker and reviewers with Focus or Peek, and Revive for a hibernated worker), timeline. The timeline also shows the reviewers' reports. Everything above the timeline's events (the task header, your-turn block with the answer field, strip, links, sessions, and the timeline's summary bar and filters) stays fixed; the events are the detail's one scroll area and fill the rest of the panel height, with no nested scroll areas and no height cap (user decision, 2026-11-26). When the panel is so short that the events would get under about 200 px, the whole detail scrolls as one area instead, so nothing clips. Jumping to the newest event on open, following new events only while scrolled to the end, and the filter chips work the same in both. The jump waits until the detail and its fixed part are measured, and a switch between the two layouts while at the end jumps again in the new scroll area. The events' room counts the bar, the fixed part and the body's paddings and gap; in the whole-detail layout the events keep no gap between them (the spine stays whole). A non-user hold reads as a sentence ("Held: Ticket closed remotely").
- Timeline: oldest first, scrolled to the end on open; rounds fold to one line with their own held-time bar, the newest two open; filters All, Decisions, Reports, Instructions; each event has a time, an actor avatar (orchestrator, worker program icon, you) and its words; decisions show the whole question and answer; a 2 px segment below each event in its holder's color, dashed while it is yours; segments longer than 30 min carry "7h 53m waiting on you". A summary bar sums time held by worker, orchestrator and you. Expansion is keyed by event time and index, so a poll never moves it.
- Answer routing: on a task whose turn is `you`, Send runs `hc send -- <orchestrator> "Answer from the herdr-app panel for <key> (bead <id>, question <comment-id>). Question: <question on one line>. Answer: <text>"`, where `<comment-id>` is the id of the `blocked reason=needs-user` comment the field was opened on. What Send reaches is decided when it is pressed, from what the detail shows then; closing the detail clears the field. Before sending, the panel reads the bead now (`liveHold`): the hold must still be `needs-user` and that comment still the newest question, else nothing is sent, the panel says the question was answered or replaced, and reloads. A draft belongs to the question it was typed under (editing the field binds it to the question on screen): when a newer question replaces it, the block says so and Send refuses until the draft is edited. After a send, only the draft that was sent is cleared. The panel's `hc send` arrives unwrapped (the app has no `HC_TERMINAL_ID` and is no terminal's child), which the skill requires; it records `decided by=user question=<comment-id>`. When the orchestrator is itself blocked (its own dialog), Send is off and the block says "Answer in the orchestrator's pane" with Focus. A worker blocked at a prompt shows "Waiting on the orchestrator" with Focus or Peek as its place allows, and no answer field.
- Pulses: on a worker's `Clock.flip` (idle or done to working: down, accent; working to idle or done: up, done color; to blocked: up, blocked color) or a fresh `orch.in` label (under 5 s old: down, accent, its kind in the card's dim line), draw an 8 px dot on the spine at its start on the render that sees it, then set its target about 50 ms later with `.transition("top", { duration: 650, easing: "ease-out" })`; the card's accent overlay fades with `.transition("opacity", { duration: 1200 })`. The pulse is armed by its timer (a flag, not a time comparison). One `cx.timer.after` per pulse ends it. Turn chips that read "Your turn" pulse a ring behind the chip with `.loop("opacity", …)`; the text stays at full opacity. No interval timers.
- Keys: `fleet.focus` gives the panel the keyboard and draws a 2 px accent ring with a filled background on the cursor card; Up and Down move between task cards, also inside the detail; Enter opens; Esc and Left close; in a detail, `a` puts the keyboard in the answer field, `f` focuses or `p` peeks at the worker (as its row offers), `r` revives it, `o` opens the PR; Ctrl/Cmd combinations pass through to the app (Ctrl/Cmd+Shift+A). `fleet.open` (shared `"fleet.open"`: `{ orch, epic, bead, at }`) draws that orchestrator whatever agent is focused, until the focus moves to an agent outside its tree, and opens the task once its session (that epic) has it; the request starts a fresh read, and it is dropped only after 20 s or when a read started after the request lacks the task (an older cached session never drops it). Render only sets state for it: `cx.notify()` is never called during render. The footer names the keys.
- Slots: `Slots n/max` counts as the skill's `slot-free.sh` does: live `w-`/`r-` terminals labelled `orch=<address>` whose own status is working.
- Accessibility: text at least 12 px (metadata 12, body 13, names 13 to 15); readable secondary text uses `muted`, `dim` only for separators and glyphs; targets at least 24 px.

### Agent rail (`mods/panda-focus`)

- Orchestrator summaries: every 30 s while the window is visible, `loadSummaries` for live orchestrators (an `[o]` pane, tab or title (`isOrchName`), an `orch-context` label, or children labelled `orch=<address>` naming a live terminal), published as shared `"orch.summary"` (`{ [address]: { epic, total, merged, inPr, you, waiting, working, text, at, youBead, youKey } }`). Each summary is built from the same rows as the panel (`buildTasks` on the newest open epic, events included), so closed, idle and hibernated tasks read the same in both. A failed read drops the summaries it couldn't read, so a stale "your turn" never lingers. An orchestrator card's sub line shows `text` ("your turn on ABC-12 · 1/4 done") instead of "1 worker working"; a red count when `you` > 0. Without a summary yet, today's text stays.
- Card times: from the rail's `Clock` (what it saw change, else the core's live `hc get` status time on first sight), never from `terminals().status_ms` alone; a parent waiting on hidden working sub-agents counts from the longest-working one's clock time. The moment each card's corner counts from (its run's start while working, else its last change) is published as shared `"panda-focus.since"` (`{ [address]: ms }`), written only when it changes.
- Ticker: when a child of a card's agent flips status, or a child's `orch.in` label is fresh, the sub line shows "↓ re-instructed w-abc-12", "↑ w-abc-12 reported" or "↑ w-abc-12 at a prompt" for 3 s, then fades with `.transition("opacity")`. One timer starts the fade and one drops it; no per-second redraw for tickers. Seen labels are forgotten after 10 s.
- `panda-focus.next-needs` (Ctrl+Shift+J, Cmd+Shift+J on macOS): the next agent in rail order whose state is blocked, or whose summary has `you` > 0, after the focused one, wrapping. A blocked agent gets `agent.focus`; an orchestrator with a waiting task gets `agent.focus`, shared `"fleet.open"` set to that task (`{ orch, epic, bead, at }`) and the Agents panel shown (`layout.select` `panel-body` `fleet`, `layout.show` `panel`).
- `panda-focus.snooze` (Ctrl+Shift+D, Cmd+Shift+D on macOS) opens the snooze menu for the focused agent, or wakes it when it is snoozed; `panda-focus.wake` wakes it (unbound). Ctrl+Shift+Z and Ctrl+Shift+W stay Herdr's zoom and tab close. Forget stays pointer-only (closed rows have no focus).
- Hibernate keeps the worker's identity: the resume label becomes `env <K=V…> <agent line>`, where `K` is each of `AGENT_BROWSER_NAMESPACE`, `BEADS_ACTOR`, `ORCH_BEAD`, `BEADS_DIR`, `BEADS_DOLT_SHARED_SERVER` found in the terminal's argv `env` prefix with a value free of whitespace (the label is for the skill's restart). Reviving from the window uses `revive.js`, which takes the whole argv from the finished terminal, so values with spaces and PATH come back too. A Codex worker is never hibernated, even labelled `hibernate=ok`.
- The session pass (`hc get` each, every 15 s) asks only about agents and terminals with a resume line, not plain shells and tools. `init` starts no pass, timer or task under `herdr-app check`.
- Fixes: import `closeOverlay`; `t3-focus.settle` comment; Working shelf header shows a red count of blocked workers and tasks waiting on the person when folded; readable text moves from `dim` to `muted` (times, branches, shelf headers, empty text, Show more, snooze labels); Settle, Snooze, Clear and the workers chip become 24 px targets; space avatar letters are never under 12 px; the arrival glow is armed by its timer.

### Sub-agents popup (`mods/panda-subagents`)

- Revive goes through `revive.js` (the launch contract from the finished terminal; the old terminal stays when the start fails), then peeks at the new one. ### Beads view (`mods/beads`, new)

- Opened as a tab: palette entry "Beads board" (`tab.new` with `{ "mod": "beads", "name": "Beads" }`), and the Agents panel header's Board button (`tab.new` with `props.epic`).
- Left: open epics from `loadAllSessions`, each with its orchestrator (live state read as the rail reads it, so one waiting on a working worker is "Working"; "Ended"; or "No orchestrator" for an epic with no `session` metadata), source, a segment bar of child states and "closed/total"; a session epic (with `session` metadata) whose children are all closed (or that has none) and whose orchestrator is gone shows "ended without --off" and a Close epic button that asks once ("Close epic?"). The confirming click reads the epic again (`epicState`) and the live terminals: still open, still a session epic of the same orchestrator, every child closed, orchestrator not live; otherwise it says why and closes nothing. Then `closeEpic` (no force: bd enforces its own rules).
- Graph: the selected epic's tasks in columns by `blocks` depth (topological levels), cards like the panel's task cards in compact form, 1 px connectors with rounded elbows; review beads ride under their task. Parallel reviewers of one round each name themselves ("Review r1 · r-abc-codex · closed"), here and in the panel's cards and session rows.
- Inspector: remote (ticket key and link from `external_ref`; state and updated time fetched for Linear by GraphQL `issue(id:)` at `api.linear.app` with the token from the login shell's `LINEAR_API_KEY`, a GraphQL `errors` answer shown as an error; for Jira by `GET <jira.url>/rest/api/2/issue/<KEY>?fields=status,updated` with `JIRA_TOKEN`, only over HTTPS and only for a ref on the origin of bd's `jira.url` config, the one source of truth for the Jira origin (the skill's `import-ticket.sh` reads the same key). The request is built from that configured base, never from the ref, a cross-origin redirect never carries the token: the app's `fetch` refuses a cross-origin redirect of a request with an Authorization header (verified on the installed runtime with a credential-free local probe, 2026-11-27: "cross-origin redirect … refused because the request carries Authorization", the second origin never contacted). `fetch` takes only method, headers and body; any other option such as `redirect` throws, so none is passed. An answer whose final URL left the origin is refused too. A Jira ref without a matching configured origin is a plain link with no remote state and no request. A refused token (401/403, or a Linear GraphQL authentication error) is forgotten, so the next attempt reads the login shell again. Absent tokens show the variable to set; the `event=note detail=remote body changed…` drift line), local (branch, base, head, worktree, labels), sessions (every `w-` and `r-` terminal that touched the bead from dispatch events and review beads: one row per worker name with its newest address, by design (a restart under the same name is the same session), and one per review round, where a closed round keeps the terminal its own events named and never takes a later round's live terminal by the reused reviewer name; live state, resume line, Focus, Peek), dependencies, and the newest events with a link to the panel's timeline. There is no Revive on the board: acting on a session goes through "Open in Agents panel".
- "Open in Agents panel" and the timeline link run `agent.focus` on the orchestrator, then set `fleet.open` (`{ orch, epic, bead, at }`) and show the panel. They are offered only when the orchestrator is live and the epic is its newest open epic; otherwise they say why.
- Read-only except Close epic. Polls the selected epic every 10 s and the session list every 30 s while this copy shows (its own pane on the current tab) and the window is visible. A read already under way for an epic is not started again, and only a result for an epic no longer selected is dropped. Arrow keys in the graph scroll the selected card into view.

### Home Manager module

- `services/herdr-app/default.nix`: `fleet` and the new `beads` mod come from `"${./mods}/<name>"`; bind `panda-focus.next-needs` (Ctrl+Shift+J, Cmd+Shift+J on macOS) in `layout:herdr-panda`.
- `custom-home-manager-options/herdr-app/default.nix`: keys merge prunes what Nix wrote before. `merge-keys.sh` keeps `$XDG_STATE_HOME/herdr-app/managed-keys.json`, which holds the last value Nix wrote per key path. A path Nix dropped is deleted from the live `keys.json` only while its live value still equals that value, so a rebind made by hand stays. Pruning and merging are one validated write. The new manifest is staged beside the old one before keys.json changes, so a failure leaves both as they were; only the final rename follows keys.json, and its failure is reported. On failure it warns, changes nothing and keeps the old manifest, so the next activation retries. It also runs when Nix has no keys left, so the last binding goes too. Sections emptied by the prune are removed; a section the person left empty stays. An old list-format manifest carries no values, so a key it lists is kept (it may be a rebind), and the legacy `mod:fleet`, `layout:herdr-fleet` and `layout:herdr-tui` entries (their values from git history) are pruned the same way when still unchanged (`layout:herdr-t3` stays: that layout still exists). `copyMod` records the files it copied per mod in `$XDG_STATE_HOME/herdr-app/mods/<name>.files` and deletes only listed files that left the Nix mod folder; files Herdr generates there stay.

### Contracts with the orchestration skill

- `orch.in=<epoch ms>:<kind>` on a worker terminal (`dispatched`, `re-instructed`, `command`), written by the skill's scripts after a confirmed send; fresh for 5 s.

- Resume labels may start with `env K=V…`; the skill's revive already parses the agent line inside.

## Testing Decisions

- Node checks load the shared modules directly (no `herdr` import): `tests/agents-shared.mjs` covers multi-word values, unknown keys, quoted values, field-like prose and multi-line questions in `parseEvent`, `holderAfter` and `held` totals on a recorded event list (a settled task's time stops; a reaped open task is the orchestrator's), `rounds` (late rounds too), every `lifecycle` stop (a newer PR report, a closed bead without a settle), `turnOf` for each turn (non-user holds), `buildTasks` worker, reviewer (two rounds under one reviewer name, a same-name worker restart), hibernated and dependency matching, `summary` text, `taskKey`, `ago`/`took` boundaries, and `Clock` first sight, fetch, `takePending` and flips. `tests/fleet-model.mjs` follows the model's new shape, with `reachOf` (no pane, pane on screen, pane off screen), slot counting, PR matching (same number in another repo, a replacement PR) and the answer message. `tests/agents-revive.mjs` checks the shared revive path with a fake `hc` (labels, env and argv kept; a failed start keeps the old terminal and its resume label). `tests/agents-bd.mjs` runs `bd.js` against a fake `bd`: the newest epic, the batched read, the rail's and the panel's rows agreeing for closed, idle and hibernated tasks, `liveHold`. `tests/fleet-render.mjs` and `tests/panda-tabs.mjs` (`node --experimental-vm-modules`) render the panel with a shared `fleet.open` (no notify during render, the named task opens whatever is focused, one scroll area in the task detail for a tall and a short panel, Send, Esc, Ctrl+Shift+A, wide and narrow) and the tab bar's per-space panel restore. `tests/beads-remote.mjs` covers the Jira origin and HTTPS rules, a token refresh after a refused token and Linear GraphQL errors; `tests/keys-manifest.mjs` runs `merge-keys.sh` (a rebind kept, a failed prune retried, an emptied section removed).
- Each mod passes `herdr-app check` on a resolved copy (`cp -rL mods/<name> "$tmp/<name>"`), never on the repository folder, which the check writes into.
- In the app after `nh home switch .`: an orchestrator with workers, a reviewer and a waiting task; a worker going working and idle (pulses); a needs-user task answered from the panel; the rail summary and ticker; Ctrl+Shift+J; the beads view on live sessions; Ctrl+Shift+A inside the panel.

## Out of Scope

- Changes to herdr-core or the app itself (live `status_ms`, an events stream for mods).
- Writing to beads from the panel; the beads view writes only Close epic.
- Syncing beads with remote trackers; remote state is read-only.
- Moving the `issues` mod's clients; the beads view keeps its own two small fetches.
